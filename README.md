# StarBreak Plugin Engine (SBPE) for Linux

This Linux-only fork adapts SBPE to the native Linux version of StarBreak.
The Windows loader and prebuilt Windows runtime are not included.
Currently tested on Ubuntu-based distributions.

### Linux build

The Linux build is currently tested with CPython 3.12 on x86-64. Install the
compiler, Python 3.12 development/venv files, SDL2 development files, and
`binutils` (for `nm`) using the package manager for your distribution:

| Distribution | Packages |
| --- | --- |
| Debian/Ubuntu | `build-essential python3.12-dev python3.12-venv libsdl2-dev binutils` |
| Fedora | `gcc gcc-c++ make python3-devel SDL2-devel binutils` |
| Arch Linux | `base-devel python sdl2 binutils` |
| openSUSE | `gcc gcc-c++ make python3-devel libSDL2-devel binutils` |

If the distribution's default Python is not 3.12, install Python 3.12 and set
`PYTHON` to its executable, for example `PYTHON=python3.12`.

From the project directory, run:

```
./scripts/build-linux.sh
```

The script can also be called by its full path from another working directory.
For example:

```
/path/to/sbpe/scripts/build-linux.sh
```
Make a copy of config_template.ini, renaming the copy to config.ini.  
Inside config.ini, put the full path to the mvmmocilent binary into de field named "game"

The script creates `.venv`, installs the exact Python package versions from
`requirements-linux.txt`, and builds both `rectbinpack/_rbp` and the native
helper `build/remote.so`. Run the loader with `.venv/bin/python loader.py`.
The helper embeds and links against the selected Python runtime, SDL2, and the
local C runtime; build it on the target machine rather than copying a Linux
binary built on another distribution. The game executable must be the native
Linux version. The script does not install system packages or use `sudo`.

The Python package pins make Python dependencies repeatable. To reproduce the
same native toolchain later, record the distribution release and versions of
Python, the C/C++ compiler, SDL2, and glibc. These system libraries are
provided by the target distribution, so compile on the machine where the
loader will run rather than reusing a binary built on a different distro.
The protobuf runtime is pinned to 3.20.3 because `bpb_pb2.py` was generated by
an older Protocol Buffers compiler and is incompatible with newer protobuf
runtimes.
